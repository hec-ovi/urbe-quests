# Integration proposals

These require orchestrator coordination. Public calls, definition fields and Engine bundle 1.2 stay in place.

| Proposal | What and why | Affected boxes / open decision |
| --- | --- | --- |
| Naming inside Quests | Add a semantic story context, completed-script naming brief and stable-ID final-name map. Quests would call an injected naming port as a creative step, validate name/type coverage, and retain names with the story and saves. Preserve world geometry/IDs and the existing named-world, types, pools and business exports. Coordinate producer ownership and consumer adapters before moving implementation. | Quests, Naming, Simulation, Engine, Materials. Authoritative naming order versus initial preview naming is unresolved; city/street identities, name extension, sign alphabet/length policy also need agreement. |
| Creation staging | Publish imported-story/final-name inputs, independent script enrichment, side-story range and per-stage ports/progress. Keep the initial writer free of gameplay tools. Define how text-plan creation and structured authoring compose into one complete caller path. | Quests, Naming, Engine. Canonical path and script-enrichment boundary remain open. |
| Instance and cast constraints | Supply available interiors, floors, role posts and semantic type mappings to adaptation/casting. Match reservations to exact compatible slots and narrative background requirements. Quests now picks story venues from a local mirror of Interior's published staffing roles and casts at the story's hour, by post; the live per-building `npc.json` roles and counts are not read. | Quests, Interior, Simulation, Engine. Whether the per-instance staffing publication reaches casting, and the failure protocol, remain open. |
| Shared locations and scene assembly | Engine scenery measures a scene's room, story slot, entrance room or sidewalk from a parcel and room kinds, and investigation 1.2 stands over it. Quests does not see a building's floors or room kinds, so its stagings stand on the ground floor, and a room kind the building lacks or a sidewalk too narrow fails only when the scene stages. Publishing floors and room kinds per building to authoring, or an Engine preflight at game creation, would refuse a scene that cannot fit before play. | Quests, Interior, Atlas, Engine. Which side checks fit (authoring data or creation preflight) remains open. |
| Shared physical rules | Publish mission-family dimensions, materials/interaction compatibility and clearances from the owning catalog for consumers. Quests currently keeps a consumed validation table for Engine v1.0. Removing it without a shared data contract would weaken the handoff. | Quests, Engine mission-assets, Modeling, Materials. Shared catalog dependency requires coordination. |
| Host capabilities and accepted actions | Extend capability negotiation beyond transportation; define theft presence blockers, accepted conversational distraction and temporary NPC action effects. Keep exact-target events and code-owned state. Model text alone cannot unlock or move things. | Quests, Engine, Simulation, Interior. Supported adventure mechanics, taxi/player-car modes and distraction protocol remain open. |
| Complete creation and handoff status | Define requested-side completion policy and retained failed artifacts; report incomplete units and required missing assets. Current side failures warn and omit definitions; supplied item bindings are validated but coverage of every physical item is not required. | Quests, Engine. Partial-side policy and complete/playable admission are unresolved. |
| Knowledge and contact | Define persistent per-person knowledge/relationships, accepted facts, contact scheduling and message/call delivery. Retain scoped dialogue segments and serialized memory; validate model replies against known/unknown facts with the selected models. | Quests, Simulation, Engine. Full graph, friendship effects and proactive contact protocols remain open; voice remains research scope. |
| Saves, time and acceptance | Coordinate story/name identity, casts, Simulation, quest state, inventory, evidence and dialogue memory in one game save. Test measured 3D traversal and the authored pessimistic story through Engine. Define waiting/time advancement with fixed night visuals. | Quests, Engine, Simulation. Complete game restore and physical traversal require the host; weekly scheduling/night interaction remains open. |
| Engine reads the 0.10.0 records | Bundle 1.1 keeps its shape with two additive fields: an authored place is `{ <identity>, name }` and a step may carry `window { label, days, startMin, endMin }`. A questline written before 0.8.5 has no place name and fails `FlowValidator`, so carried quest sets need one materialize pass. `stepAvailability` adds the reason `outside_window` for a step outside the hour its own text names. Casting at load is `new CastResolver(sim, new StoryVenues(world, types)).cast(definition, timeMin, options)`, answering `{ cast, posts, blocked? }`: the host plays the definitions the bundle carries (their places are final, pinned while the questline was built, so the interiors it opens from the steps are the ones the story uses), reads `cast` as before, ignores `posts`, and lists a `blocked` questline in the menu with `blocked.reason` instead of dropping it. Without the world it still casts at the story's hour but can only try the pinned venue, so characters of one type can double up. Materialize takes `--parcels=<ids|@file>`: run it once open to learn which buildings the story wants, open those interiors, then run it again with the ones that opened, and the bundle names only those. `questlines.meta.json` carries the set under `parcels` and anything left out under `blocked`. | Quests, Engine. The HUD wording for a closed hour and for a blocked questline is the host's. |
| Output versioning | Negotiate versioned story, runtime and creation envelopes where current outputs have no version field. Preserve existing closed schemas and bundle 1.2 until consumers agree. | Quests, Engine and authoring callers. No uncoordinated envelope changes. |
