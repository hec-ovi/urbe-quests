# Changelog

0.13.1: `npm run author` checks every input before it asks the model server anything: an option never takes the next option as its value, the open parcels must name buildings the world has, and the handoff file passes the handoff boundary. A creation run refuses an empty `parcels` list or an unknown parcel id before any model is asked, and `readHandoffInput` checks the file it reads. Each plan lands on disk and in `recording.json` once it parses, before its build, through a new `plan` progress event (`planned` on a translation), so a failed build keeps its plan. A server the author cannot reach fails as stage `model` with `meta.json` written, and every request failure names the address and the reason. Documents and data drives are at least 12.5 mm high in the handoff, the height Engine's geometry needs in every variant.

0.13.0: `npm run author` writes a story with a live OpenAI-compatible model and makes it a bundle in one run: each stage lands in `--out` as it finishes, progress streams to stderr, `recording.json` keeps what the model said, lands with every stage and build round, and replays to the same questlines, `meta.json` carries the model, the inputs and the elapsed seconds at which each stage landed, and the recording is materialized in-process into bundle 1.1 with the same `--parcels` a later `npm run materialize` would take. It is the one live authoring CLI. A host that plays only some mechanics names them (`mechanics`, `--mechanics`): the planner and builder see only those kinds' catalog sections and tool fields, a step of another kind is refused by name, and a recording keeps the list so replay meets the same refusals. One mission item template per physical item kind ships with the box and is checked before a run; the handoff refuses a material kind the family cannot wear. Situation titles are distinct from each other and from the script's, a title copied from the format is written again, a side quest built under an id another questline holds is dropped, and an empty `LLM_MODEL` or `LLM_API_KEY` counts as unset. The builder answers a target missing a field with what its kind takes, tells a model that resends a refused call that nothing changed, and reports each round's refusals in `BuildProgress.refusals`; the sample client asks for parallel tool calls.

0.12.1: A model's cue tag becomes a listed cue when its first or last word is a cue or a form of one, so `[sighs heavily]`, `[chuckling]`, `[a bitter laugh]` and `[[sigh]]` reach the voice. Dropping a stage direction never leaves a tag outside the list, even inside another bracket, and the streamed text still matches the whole reply. `stripCues` leaves one space where a cue sat between two words and opens single-quoted lines cleanly. Authored lines write each cue exactly as the list does.

0.12.0: NPC lines carry emotion as inline cues from one closed list, `[laugh] [sigh] [whisper] [angry] [gasp] [cry]`, exported as `CUES` with `stripCues(text)` for display on both entries. Free-chat replies may use a cue where the sound or manner happens, sparingly; the streamed text keeps them whole however the model splits them, a model's `[Sighs]` comes out as `[sigh]`, and any other bracketed tag is dropped. A wrapping quote pair goes even with cues in front of or behind it, a reply of cues alone is no reply, and memory stores replies without their cues. Authored openings and replies may carry the same cues; the validator refuses any other bracketed tag in them and any tag in the player's text.

0.11.1: NPC replies keep their punctuation and stop where the NPC's turn ends. A reply that opens with a quote loses the pair only when that quote closes at the end; a template token after the reply ends it, a start token before it drops its role line, and a streamed reply stops reading the model once it has moved past the NPC's turn. Offers arrive after the spoken reply, so a failed turn offers nothing, and a follow-up request echoes malformed tool arguments as `{}`. Memory notes lose only markup and an empty note keeps its turns for the next fold. The now line says what the NPC is doing in plain words, and station and vehicle workers name the stop or the lines they work. Think blocks and template tokens have one stripper, shared with the creation sample client.

0.11.0: NPC chat speaks as the person Simulation made and can go somewhere with the player. The person lines carry gender, age and traits; the dark-tone rules let a grim city sound grim; districts, buildings and stops are named or plainly described, never shown by id. `Converse.replyStream` streams cleaned text over an OpenAI-compatible `StreamingLLMPort` and, in the same request, turns `follow_player` and `lead_player_to` tool calls into offers the host decides on; a tool-only answer gets its spoken reply from one more request. `contextFor` takes a guided place with scene notes, `recordExchange` stores only completed exchanges and folds memory after the reply, and one reply cleaner serves replies and memory notes. `chatDeltas` reads the SSE body and its token usage for every streaming port.

0.10.5: Last Call at Oxide Filter now describes the theft it actually runs: district observation identifies the guard and his route, then the player follows the marked guard and takes the bagged notes he carries. Recorded situation, plan, item, dialogue and objective prose agree without changing quest targets, cast, progression or saved-state shapes.

0.10.4: talk steps carry authored offline openings, informational replies and explicit commitments. Runtime conversations bind one quest step to its exact cast, return current availability, and reject stale or blocked selections without mutation. Only a completing choice advances that one step; opening, closing and typed chat do not. The Weir Line and all three recorded side stories cover all 15 talks, including explicit expose and settlement endings. Legacy definitions receive fallback choices; bundle 1.1 and saved-state shapes are unchanged.

0.10.3: roles preserve authored character names as optional display metadata independently of generated NPC identities. Recorded unreserved roles retain the script's names without reserving people. Scoped dialog context and replies use the same character name while simulation names, cast IDs, routines and bystanders remain unchanged.

0.10.2: materialize creates exact portable pickup assets from authored item-kind templates and preserves explicit bindings. Handoffs reject missing pickup bindings or assets without a portable take anchor instead of publishing an impossible collection step.

0.10.1: casting searches real weekly staffing posts when a game opens outside business hours and never assigns different characters to the same person. Live hosts can check authored talk/listen appointment eligibility before placing the cast, while quest completion still requires their exact physical presence, the authored hour, items and conditions.

0.10.0: a creation run takes the buildings the story may use (`parcels`, `--parcels=<ids|@file>` on materialize) and keeps every place inside them: venues are chosen from the set, a building outside it moves to one of the same kind that is in it, and a questline with nowhere to go is named with its reason instead of shipped. A host that opens part of the city gets a bundle that only points at buildings the player can walk into.

0.9.1: where a step happens is settled while the questline is built. Casting reads the questline and reports the building each character holds a post in; the creation stage pins with it, so the bundle ships the final places and a host at load plays them. A step moves only for the people it meets, only to a building one of them holds a post in, so a character found off a post never pulls a story onto their own address.

0.9.0: a published step and its cast name the same place. The simulation says where the city hires, a building published for residents alone is no story venue, and a questline nobody can staff is published blocked with its reason instead of disappearing.

0.8.5: a quest place carries the venue's name and a step that names an hour carries the window the runtime checks. Story venues are buildings that publish a post for the character, the cast is queried at the story's own hour, and one person plays one character across a questline set. Engine bundle 1.1 gains those fields and keeps its shape.

0.8.4: each box's tests cover its contract surface once, on the sample recording the launcher replays.

0.8.3: separate story and gameplay agents share deterministic flow validation; tool descriptions and prompts are Markdown assets. The sample client streams uncapped text and tool calls. Engine bundle 1.1 uses schema-validated handoff inputs. Compiled library output includes standalone fixtures; replay output stays local. API calls live in the root skill and contract; open integration proposals live in docs/ISSUES.md.
